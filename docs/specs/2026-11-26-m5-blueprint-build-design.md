# M5 設計：影片 → 藍圖 → 施工（2026-11-26）

> 本文件取代 `2026-11-05-architecture-design.md` 第 5 節的 M5 那一列，以及 4.4 節列出的 M5 工具清單。
> 其餘章節不變。與前文衝突時以本文件為準。
> 調查依據見 `docs/research/2026-11-25-minecraft-agents-and-blueprints.md`。
> 標「**user 決定**」的是 user 在 2026-11-25／26 的討論中明說或同意的；標「**我的決定**」的是 Claude 的判斷，user 可推翻。
> **第 2 節的表格逐列標示。第 3 節以後沒有另外標示的內容，一律是「我的決定」**：user 同意的是表格裡的方向，細節是 Claude 提的。

## 1. 意圖

給機器一段別人的建築短片，它在 Pokopia 的空地上蓋出結構對得上的建築。user 只在動工前確認藍圖，動工後不介入。
（影片轉藍圖的過程裡確認分兩次，見第 5 節；這取代原規格 M5「人全程不介入」的驗收。）

中間多一層**藍圖**：不論影片長什麼樣，都先轉成同一種固定格式，施工只認藍圖。
這樣「看懂影片」和「蓋得出來」兩件事可以分開做、分開驗收。

## 3. 四個計畫

| 計畫 | 內容 | 需要主機 | 依賴 | 風險 |
| --- | --- | --- | --- | --- |
| **A 藍圖格式與工具** | 格式、檢查程式、材料清單、預覽網頁 | 否 | 無 | 低 |
| **B 影片 → 藍圖** | 抽關鍵幀、模型逐層產出、程式檢查、user 確認 | 第 0 階要 | A | 高：沒有前例 |
| **C 定位與多種物品** | 走到指定格、記住自己在哪一格、換手上的物品。**不含挖地和階梯**，那兩項是 M5c 前的擴充（見下） | 是 | 無 | 高：用畫面定位在業界未解 |
| **D 照藍圖施工與拆除** | 比對 → 取差異 → 做一格 → 再比對；逐層對帳；缺料或到不了時暫停；蓋完依施工紀錄拆除復原 | 是 | A、C | 中 |

順序：A 先做。B 和 C 可以同時進行。D 最後。每個計畫各自寫計畫檔、各自驗收。

### 里程碑

| 里程碑 | 內容 | 驗收 |
| --- | --- | --- |
| **M5a 照藍圖施工** | A、C、D | 給一張手寫藍圖（5×5 底面、兩種方塊、底座加一面兩層的牆），機器蓋出來。**每一格的方塊種類都與藍圖相同才算過**，判定方式見第 6 節；花費不超過 US$5、不超過 1 小時；拆除後場地復原，判定方式見第 6 節 |
| **M5b 影片 → 藍圖** | B，第 0 階與第 1 階影片 | 見第 5 節 |
| **M5c Larvitar** | 先擴充：階梯與朝向、挖地（含第 6 節的逐格原狀紀錄與復原）。再用 M5b 的流程產出 Larvitar 的藍圖，由施工器蓋出結構 | user 目視認可結構「像」 |

M5a 的手寫藍圖只用整塊的方塊，不挖地、不用階梯。裝飾品放置、材料蒐集與合成不在 M5，之後另開。

## 4. 藍圖格式（方向；欄位細節在計畫 A 定）

文字檔，模型寫得出來、人看得懂、程式能檢查。

- **對照表**：一個符號對應一種方塊。有朝向的方塊（階梯）一個朝向一個符號。方塊名稱只能用 pack 的物品清單裡有的。
- **逐層平面圖**：由下往上，每層一張；每列一個字串，一格一個字元。
- **座標約定寫在檔案裡**：原點在哪一角、列和欄各往哪個方向、哪一層是最底層。施工器只認這個約定，不讓模型換算。
- **裝飾品另列清單**（名稱、位置、朝向），不混進方塊格子。M5 不蓋，但留著給之後用。
- **每層標可信度**：看得清楚／推測／猜的。user 檢查時先看後兩種。
- **來源**：這一層是依據影片哪幾格畫面判斷的。手寫藍圖可省略。

由程式做、不由模型寫的：

- 每列長度與宣告的尺寸相符、符號都在對照表裡。
- 材料清單（每種方塊幾個）。
- 每層的方塊數，施工後用來對帳。
- 懸空的方塊（下方沒有支撐）標出來提醒，不擋下。
- 預覽圖。

## 5. 影片 → 藍圖（計畫 B）

### 影片分階

| 階 | 來源 | 用途 |
| --- | --- | --- |
| 第 0 階 | 我們自己的畫面：機器用 routine 蓋出已知形狀，繞一圈存截圖 | 有標準答案，可以算格子正確率 |
| 第 1 階 | user 找的簡單影片：方塊 1–2 種、3 層以內、少裝飾、720p 以上、完成後有繞一圈或俯視 | 真實影片上的表現 |
| 第 2 階 | `Pokopia-5x5-Larvitar` | M5c |

現有的 M4 錄影是除錯過程，不適合當第 0 階（2026-11-26 看過）。第 0 階的畫面要重新在主機上取。

### 流程

1. 抽關鍵幀，裁掉社群短片上下的模糊邊。
2. 模型估整體尺寸、層數、方塊種類。**user 確認（第一次）**：只看幾個數字，尺寸錯了後面全錯。
3. 模型逐層產出平面圖，每層分開問，帶上已確定的下層。
4. 程式檢查（第 4 節）。不合格的層退回重問，有次數上限。
5. 產出預覽網頁。**user 確認（第二次）**，可以指出有問題的層，只重做那幾層。

確認分兩次是我的決定。user 同意的是「看過才動工」；若只想看一次，就把第 2 步併進第 5 步，代價是尺寸估錯時整份重做。

### 驗收

- 第 0 階：至少 5 個已知形狀，回報格子正確率與尺寸正確率。**及格線在量到第一批數字後由 user 定**；目前沒有任何數字可以當依據。
- 第 1 階：user 看預覽網頁，修改不超過約定的格數（同上，量到後定）。

## 6. 定位、施工與拆除（計畫 C、D）的原則

細節等實機實驗後寫進各自的計畫。現在只定原則：

### 施工

- 座標由程式記，不由模型估。每個移動 routine 更新座標，並用畫面確認。
- 用已蓋好的方塊或另外放的參考方塊校正位置。可行性要實機驗證。
- 每放一格都確認三件事：預覽框在程式記的那一格、手上是藍圖要的那種物品、放完後**那一種物品**的背包數量減一。
  前兩件 M4 已有；用數量確認材質是新的。
- 成功與否由獨立的檢查決定，不採信執行者自己的回報。
- 同一格連續失敗有上限，超過就暫停並說明卡在哪裡，不無限重試。

### M5a 的判定（逐格）

上面的逐格確認都依賴程式記的座標，座標一旦偏掉，數量對了位置也可能全錯。所以驗收另外要一個不依賴它的觀察：

- **每蓋完一層、還沒被上一層蓋住之前**，機器存一張能看到這一層每一格的截圖（俯視或接近俯視）。機器不停下來等人。
- 全部蓋完後再從四個方向各存一張。
- **user 拿每一層的截圖對照藍圖那一層的平面圖，逐格確認種類和位置**。M5a 以這個為準；四個方向的圖只用來看整體。
- 如果機器取不到能看清一層每一格的截圖（鏡頭控制目前只有俯仰和小角度水平轉動），M5a 改由 user 在旁邊看著蓋來判定，
  並在驗收紀錄寫明是人工觀察。這種情況下不算達成「動工後不介入」。
- 由程式或模型從截圖讀回「現在蓋成什麼樣」是計畫 B 第 0 階在量的同一種能力。量到夠準以後，才把這一步改成自動；在那之前不宣稱自動驗收。

### 中斷與續蓋

- 進度（哪一層哪一格已放並確認）和施工紀錄存在程式管的檔案裡。
- 續蓋前不能只信檔案：要先在畫面上重新確認位置和最後幾格的現況。**怎麼重新確認還沒有做法**，計畫 D 用實機實驗定。
  定出來以前，中斷後的處理是拆除重來，不續蓋。

### 拆除與復原（計畫 D）

- **M5a 的藍圖不挖地**，所有方塊都放在原本的地面上。拆除就是把放上去的拿掉。
- 施工紀錄記下每一個放上去的方塊（座標、種類），包含校正用的參考方塊。
- 拆除只動紀錄裡的格子，範圍限制在藍圖的底面加一圈，不碰原本的地形。
- 拆除也會中斷：拆到哪裡同樣記在檔案裡。
- M5a 復原的判定，三項都要成立：
  - 紀錄裡的每一格都拆除並逐格確認（M4 已有：破壞後的撿取通知）。
  - 每種用到的物品，背包數量回到施工前的數字。
  - 施工前和拆除後各存一張涵蓋整個範圍的俯視截圖，user 對照確認地面沒有變。
- **挖地是之後的事（M5c 的 Larvitar 需要），到時要先補上這些才能做：**
  - 挖之前記下那一格原本是什麼方塊（挖出來進背包的物品就是它的種類）。
  - 填回時照紀錄逐格放回原本的種類，逐格確認。
  - 復原的判定逐格比對紀錄，不只看總數。

## 7. 還沒定與未查證

- 第 0 階和第 1 階的及格線（第 5 節）。
- 用參考物校正位置是否可行；鏡頭轉正的量測方法（空草地上找不到線）。
- 續蓋前怎麼在畫面上重新確認現況（第 6 節）。
- 機器能不能自己取得俯視和四個方向的截圖（鏡頭控制目前只有俯仰和小角度水平轉動）。
- Pokopia 的階梯有幾種朝向、怎麼切換；挖地後的地面在藍圖裡怎麼表示。
- 逐層分開問是否比一次問完準：調查沒有找到實測，要自己量。
- 調查中標「僅摘要」的項目沒有當依據。

## 8. 與原規格的差異

- 原本 M5 是一個里程碑，現在拆成 M5a、M5b、M5c。
- 原本 M5 驗收寫「人全程不介入」；現在 user 在動工前確認藍圖（最多兩次），M5a 的驗收由 user 看截圖判定。
- 原本每月上限 US$50；2026-12-01 起暫定 US$80。
- 原本 M5 包含上網查配方、蒐集材料；現在移出 M5。
- 原本驗收是「評審認可像」；現在 M5a、M5b 有可以量的條件，M5c 才是 user 目視。
- 原本的 `analyze_build_video`、`lookup_recipe` 工具清單作廢；`walk_to`、`face`、`place_block`、`select_move` 的需求併入計畫 C。
- 階梯與挖地從 M5a 移到 M5c 前的擴充。
- 第 1 節「專案的本體是遊戲無關的機械層」不變，但不再要求 M5 的流程能給別的遊戲用。
