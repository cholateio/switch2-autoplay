## 1. 目標

做一套能自動玩 Nintendo Switch 2 的系統，第一個目標遊戲是《Pokémon Pokopia》。

架構是「電腦用眼睛看、用手按」的閉迴路：

```
擷取卡畫面 → Python 視覺辨識（現在是什麼狀態？）→ 決定動作 → 送指令給 ESP32-S3 → ESP32-S3 假扮手把按給 Switch → 再看畫面確認結果…
```

不改機、不讀遊戲記憶體，只用一般手把輸入。

## 2. 硬體與接線（已採購）

| 項目 | 說明 |
|---|---|
| Switch 2 | 放在底座上，HDMI 輸出接擷取卡 |
| 擷取卡 | USB 接電腦，型號待確認（見文末問題） |
| ESP32-S3 開發板 | 雙 Type-C 副廠板，模組 ESP32-S3-WROOM-1 N16R8，USB 轉串口晶片是 **CH343P** |
| 線材 | 兩條支援資料傳輸的 USB-C 線 |

```
電腦 ──USB──▶ ESP32-S3【USB to Serial (CH343P) 口】
              ESP32-S3【ESP32-S3 原生 USB / OTG 口】──USB──▶ Switch 2 底座 USB
Switch 2 底座 HDMI ──▶ 擷取卡 ──USB──▶ 電腦
```

- 兩個 Type-C 口**不能互換**：OTG 口當手把接 Switch，串口那個接電腦。
- CH343P 在 Windows 上可能要裝沁恆（WCH）的 CH343SER 驅動，裝置管理員才會出現 COM 埠。

## 3. 已知的技術限制（請照這些設計）

### Switch 2 主機設定
- 開啟「Pro 控制器有線通訊」。
- **關閉 HDR**（電視輸出那一個選項）、色彩維持正常（不要灰階或反轉）、文字大小維持一般、主題用亮色或暗色。
- 遊戲重開時游標會跳回第 1 個使用者，所以要使用的帳號必須放在最左邊。
- 很多遊戲同時只吃一支手把：ESP32-S3 和實體手把要輪流用。

### 時序（來自 Pokémon Automation 專案的實測）
- Switch 2 對有線手把的輪詢率會在 125 Hz 和 62.5 Hz 之間浮動，所以**任何手把狀態都至少要維持 16ms** 才能確保被讀到。
- 一般按鍵要按住約 **40ms 以上** 才會被認成一次按下。預設按壓時間建議 50–80ms。
- 系統選單比 Switch 1 慢；數字鍵盤、虛擬鍵盤的捲動要間隔 **48ms** 才穩。
- 有些在 Switch 1 有效的「同時按、重疊按」技巧在 Switch 2 上會失效，不要依賴。

### 手把模擬能力
- 有線 Hori 類手把模式：14 個按鍵 + 十字鍵 + 兩支 8-bit 類比搖桿。**沒有陀螺儀、震動、NFC。**
- 動森基本上不需要陀螺儀。

## 4. 手把控制的兩條路（請評估後建議）

### 路線 A：使用 Pokémon Automation 的 PABotBase2 韌體
- 原始碼：GitHub `PokemonAutomation/ComputerControl`（請先確認授權條款）。
- 優點：已在 Switch 2 上實測可用，支援 NS1/NS2 有線手把、有線 Pro 手把。
- 需要研究它的序列埠協定，然後用 Python 自己實作送指令的那一端。
- 刷韌體：Espressif Flash Download Tool，選 ESP32-S3，燒 `PABotBase2-ESP32-S3-<version>.bin`，位址 0x0，鮑率 460800。

### 路線 B：自己寫韌體（ESP-IDF + TinyUSB）
- 讓 OTG 口偽裝成 HORI Pokken Tournament Pro Pad（VID `0x0F0D`、PID `0x0092`），這是已授權的有線手把，Switch 不需要配對。
- HID 回報是 8 bytes：按鍵 16 bit、十字鍵（0–7 方向，8 = 置中）、LX、LY、RX、RY（0–255，128 = 置中）、1 個保留 byte。
  - 描述符和按鍵位元順序**請對照參考實作驗證，不要憑記憶寫**，例如 `shinyquagsire23/Switch-Fightstick` 這類 Pokken 模擬專案。
- 電腦端經 CH343 串口送封包，建議格式：`[0xAA][buttons_lo][buttons_hi][hat][lx][ly][rx][ry][seq][crc8]`，鮑率 921600 或 115200。
- 韌體每次被 Switch 輪詢時就回傳「最新狀態」。
- **必要的安全機制**：超過 300ms 沒收到封包，就自動回到「全部放開、搖桿置中」，避免電腦當掉時角色一直往前跑。
- 要先確認 Switch 2 能吃這個描述符（理論上可以，Switch 2 相容 Switch 1 的有線手把）。

### 我的初步想法
1. **第一步先零程式驗證硬體**：刷 PABotBase2 韌體，用 Pokémon Automation 官方程式的鍵盤控制確認 Switch 2 有反應。這樣可以先排除接線和驅動的問題。
2. 之後我自己的程式碼，傾向用**路線 B**（協定簡單、完全掌控、容易除錯）。如果你讀過 PABotBase2 原始碼後覺得路線 A 的協定更好接，請說明理由。
3. 不論選哪條，Python 這邊都要有一個抽象的 `Controller` 介面，後端可以抽換。

## 5. 軟體架構

語言：Python 3.11+，主要套件 OpenCV、numpy；設定檔用 YAML。

```
switch_auto/
├── capture/        影像來源：擷取卡（OpenCV / ffmpeg 管線）、影片檔、圖片資料夾
├── controller/     Controller 抽象介面 + 後端：serial（路線 A 或 B）、dummy（只印 log）
├── vision/         ROI 定義、模板比對、顏色判斷、（之後）OCR
├── states/         遊戲狀態偵測器：每個狀態一個 detector，回傳 是/否 + 信心值
├── tasks/          具體任務（狀態機），例如「對話自動推進」
├── runtime/        主迴圈、看門狗、緊急停止、錯誤時存截圖
├── tools/          校準工具、截圖/標註模板工具、巨集錄製與重播
├── firmware/       （路線 B）ESP-IDF 專案
└── tests/
```

### 已有的程式碼
我已經有一支 `capture.py`（會一起附給你），功能包括：
- OpenCV 直接開擷取卡，或用 ffmpeg 管線讀 BGR 原始畫面。
- 背景執行緒**只保留最新一張畫面**，分析慢只會跳過舊畫面，延遲不會累積。
- 顯示實際 fps、畫面延遲、全黑偵測；按 `s` 存全解析度截圖。

請把它整理進 `capture/` 模組，保留這些設計。

### 設計原則
1. **所有座標以 1920×1080 為基準**，實際解析度不同時自動換算。ROI 和模板都用這個基準存。
2. **每個動作都要「做 → 確認」**：按下去之後要用畫面確認狀態真的改變，沒變就重試，重試超過上限就停下來，存截圖並記錄原因。不要寫盲目的長串巨集。
3. **能離線開發**：影像來源可以換成錄好的影片或截圖資料夾，手把可以換成 dummy。沒接主機時也要能跑測試。
4. **緊急停止**：一個全域快捷鍵（例如 F12），按下去立即送「全部放開」並停止任務。
5. **紀錄**：每次執行存 log；失敗時自動保存前後幾張畫面，方便除錯。
6. 時序常數（按壓時間、最短狀態維持時間、選單間隔）集中放設定檔，不要寫死在程式裡。

## 6. 里程碑與驗收標準

**M0 – 硬體驗證（不寫程式）**
- 刷 PABotBase2 韌體，用 Pokémon Automation 程式的鍵盤控制能在 Switch 2 主選單移動游標。
- `capture.py` 能穩定顯示 Switch 2 畫面，記下實際解析度、格式和 fps。

**M1 – 手把通訊**
- 完成 `Controller` 介面和 serial 後端（路線 A 或 B）。
- 指令列工具：`python -m switch_auto.tools.press A`、`hold LSTICK_UP 500ms` 這類。
- 驗收：在主選單用程式移動游標並開啟設定，重複 100 次不漏按、不卡鍵。
- 拔掉電腦端 USB 時，角色不會一直往前跑（安全機制生效）。

**M2 – 擷取 + 視覺基礎**
- 擷取模組化，支援擷取卡、影片檔、截圖資料夾三種來源。
- 模板工具：在截圖上框 ROI、存成模板，並記錄比對門檻。
- 驗收：用 10 張以上的截圖測試，能正確判斷「主選單 / 遊戲中 / 黑畫面讀取中」。

**M3 – 第一個閉迴路任務（動森）**
- 任務：**對話自動推進**。偵測到對話框就按 A，對話框消失、回到可操作狀態就停止；出現選項時停下來通知我。
- 驗收：和村民對話 20 次，全部自動推進完，沒有誤按造成選錯選項。

**M4 – 移動與校準**
- 校準工具：量測「搖桿推 N 毫秒，角色大約移動多遠」，以及鏡頭重置的方法。
- 用畫面特徵修正方向（閉迴路），不要只靠時間推算。
- 第二個任務等 M3 完成後再一起討論。

每個里程碑完成後，請停下來讓我實機測試，再進下一個。
